# Waylo Desktop (macOS)

The macOS companion to the Waylo Android app. Waylo Desktop reads the UI of any
frontmost Mac app via the Accessibility API, draws an animated pulsing red dot
over the exact element you need to click next, and speaks each step aloud. Step
plans are generated by the existing Waylo backend (shared with Android), with a
Gemini Vision fallback when an element can't be found locally.

## Requirements

- macOS 13.0+
- Xcode 16+ (developed against Xcode 26.2)

## Opening & building

```bash
open WayloMac.xcodeproj
```

Or from the command line:

```bash
xcodebuild -project WayloMac.xcodeproj -scheme WayloMac -configuration Debug build
```

The project uses an Xcode "synchronized" file group, so any file added under
`WayloMac/` is automatically included in the target — no manual project edits
needed.

## Configuration — backend URL

The backend URL is **never hardcoded in source**. It is resolved in this order:

1. `WAYLO_BACKEND_URL` environment variable (handy for local dev / tests; set it
   in the scheme's Run → Arguments → Environment Variables).
2. The `WayloBackendURL` key in `WayloMac/Info.plist`.
3. A `http://localhost:3000` fallback.

Set the Railway URL in `Info.plist` (replace `https://YOUR_RAILWAY_BACKEND_URL`)
or pass it via the environment variable for the scheme.

## Permissions

Waylo needs **Accessibility** access to read other apps' UI. On first launch the
onboarding window guides you to:

System Settings → Privacy & Security → Accessibility → toggle **Waylo** ON.

Screen Recording (for the vision fallback) and Microphone (for voice input) are
requested on demand.

> **App Sandbox is disabled** in `WayloMac.entitlements`. A sandboxed app cannot
> call `AXUIElementCreateApplication` on other processes or install global event
> monitors — the same reason tools like Alfred and Raycast aren't sandboxed.
> Hardened Runtime is enabled for future notarization.

## How it runs

- Menu-bar only (no Dock icon). Click the menu-bar icon (`cursorarrow.rays`) or
  press **Cmd+Shift+W** to toggle the floating task panel.
- Type a task ("how do I bold text in Word"), or use the mic button.
- The backend returns steps; the dot guides you click by click.

## Architecture

```
WayloMac/
├── WayloMacApp.swift            @main, menu-bar app (no Dock icon)
├── AppDelegate.swift            lifecycle, status item, global hotkey
├── accessibility/
│   ├── AccessibilityReader.swift  reads the AXUIElement tree of frontmost app
│   └── ElementFinder.swift        scoring-based element search
├── overlay/
│   ├── OverlayWindow.swift         transparent, always-on-top, click-through
│   ├── OverlayWindowController.swift  manages the dot window (singleton)
│   └── DotView.swift               SwiftUI pulsing red dot
├── guidance/
│   ├── GuidanceEngine.swift        orchestrator (singleton, @MainActor)
│   └── FallbackHandler.swift       in-memory screenshot → backend → Gemini
├── ai/
│   ├── AppConfig.swift             backend URL resolution
│   ├── WayloAPIClient.swift        HTTP calls to the Railway backend
│   └── PlanParser.swift            tolerant JSON decoding
├── voice/
│   ├── Speaker.swift               AVSpeechSynthesizer wrapper
│   └── MicHandler.swift            SFSpeechRecognizer voice input
├── models/Step.swift              Step + GuidePlan models
└── ui/
    ├── HomePanel/…                 floating task input + dev tools
    ├── OnboardingView.swift        accessibility permission flow
    └── OnboardingWindowController.swift
```

### Element finding (three layers)

1. **AX tree search** — instant, offline, via `ElementFinder` scoring.
2. **Vision fallback** — capture the screen in memory, send to the backend's
   `/vision-fallback` route (Gemini Vision), re-search with the corrected
   description. Screenshots are **never written to disk**.
3. **Manual** — if still not found, the user clicks and guidance continues.

## Developer tools / milestones

Open the panel and click the hammer icon to reveal dev tools that map to the
build milestones:

1. **Log frontmost AX tree** — prints all interactive elements of the frontmost
   app to the Xcode console (open Excel, click it, see toolbar buttons logged).
2. **Show/Hide test dot** — draws the pulsing dot at a hardcoded point to verify
   the overlay floats above other apps.
3. **Find element** — type "Bold button", press Find, and the dot lands on the
   matching element (validates the offline pipeline end-to-end).

Then type a real task in the main field to exercise the full AI + guidance flow.

## Backend

The shared Node backend (`../backend_initial`) was extended with:

- `/plan` now branches on `platform: "macos"` and returns
  `{ task, app, steps:[{ index, instruction, findDescription }] }`.
- A new `/vision-fallback` route for desktop screenshot analysis.

The Android `/plan` and `/vision` contracts are unchanged. The macOS
`PlanParser` is also tolerant of the mobile response shape (`stepNumber`,
`appName`) so it works against either contract.
